2. In-Depth Algorithm Explanations

1️⃣ Hashing (Dictionary Lookup) O(1)

Implementation: self.active_vehicles = {} in parking_manager.py.

When a vehicle attempts entry, instead of scanning all 30 slots or performing a slow SQL database scan, the system hashes the normalized vehicle registration number (e.g. hash("KA-01-AB-1234")) to achieve instant O(1) duplicate detection.

# O(1) Duplicate Check in parking_manager.py: if normalized_num in self.active_vehicles: return { "success": False, "message": f"Duplicate vehicle! Already in Slot..." }

2️⃣ Linear Search (Slot Allocation) O(N)

Implementation: find_first_available_slot(category).

Iterates through the 30 fixed parking slots sequentially. Checks both availability status and category eligibility (e.g. EV fallback, Two-Wheeler restriction).

  • Best Case: O(1) if Slot S-01 is available.
  • Worst Case: O(N) if only Slot S-30 is free or if parking is full.
for slot in self.slots: # N = 30 slots if slot.is_available() and slot.is_eligible_for(cat): return slot return None # Parking full -> sends to queue

3️⃣ FIFO Waiting Queue (Deque) O(1)

Implementation: self.waiting_queue = deque() from collections.

Why not list? In Python, list.pop(0) takes O(N) because all remaining elements must shift. collections.deque is a doubly linked block list, guaranteeing O(1) for both append() and popleft().

# O(1) Enqueue when parking is full: self.waiting_queue.append(queue_item) # O(1) Dequeue on vehicle exit: assigned_item = self.waiting_queue.popleft()

4️⃣ Merge Sort & Quick Sort O(N log N)

Implementation: Custom recursive divide-and-conquer in parking_manager.py.

Sorts historical records by vehicle number, entry time, duration, or fee. Recurrence relation: \( T(N) = 2T(N/2) + O(N) \implies O(N \log N) \). Merge Sort is chosen because it guarantees stable sorting with consistent \( O(N \log N) \) worst-case time.

def _msort(arr): if len(arr) <= 1: return arr mid = len(arr) // 2 return _merge(_msort(arr[:mid]), _msort(arr[mid:]))
